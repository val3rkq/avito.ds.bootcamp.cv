# Ориентация текстового кропа: 0/180 градусов

Предсказание `p_180` — вероятности, что кроп текста перевёрнут вверх ногами. Метрика: 1 − Brier.

## Данные

Архив `test.zip` распаковывается **в корень репозитория**, чтобы в корне было:

```
sample_submission.csv
test/images/test_00000.png ... test_19999.png
```

## Попытка 1

Готовый классификатор угла из PaddleOCR (`ch_ppocr_mobile_v2.0_cls`, MobileNetV3, вход 3×48×192) **без дообучения**.
Для длинных строк (w/h > 4) кроп режется до 4 окон шириной 192, логиты усредняются.

Антисимметричный TTA: `z = (logit(x) − logit(rot180(x))) / 2`, `p = σ(z)` --- гарантирует, что `p(x) + p(rot180 x) = 1`.

Open-source компоненты: PaddleOCR / RapidOCR (модель, препроцессинг), onnxruntime, OpenCV.

**LB: 0.91.**

Запуск через Docker:

```bash
docker compose run --rm app baseline_paddle --out outputs/submission_v1.csv
```

## Попытка 2: своя модель на псевдо-размеченном тесте

Один скрипт делает всё — от предсказаний попытки 1 до `submission_v2.csv`; каждый промежуточный
артефакт берётся с диска, если есть, иначе создаётся:

| этап | артефакт | что делает |
|---|---|---|
| 1 | `outputs/submission_v1.csv` | предсказания попытки 1 (PaddleOCR cls); нет — считает бейзлайн |

| 3 | `weights/v2/orient_mnv3s.pt` | обучение MobileNetV3-small с антисимметричной головой на CPU |
| 4 | `weights/v2/orient_mnv3s.json` | temperature scaling на val, метрики |

## Попытка 3: смесь попыток 1 и 2

`p = (p_v1 + p_v2) / 2` — тот же скрипт, с готовыми весами:

```bash
docker compose run --rm app submission_v2 --blend-v1 0.5 --out outputs/submission_v3_blend.csv
```

Зачем: Brier выпукл по `p`, поэтому Brier смеси ≤ среднего Brier'ов двух моделей, а при некоррелированных
ошибках смесь лучше обеих. На лёгких кропах доминирует уверенный PaddleOCR (v1), на трудных студент (v2)
добавляет знание домена. Обе модели антисимметричны, свойство `p(x) + p(rot180 x) = 1` у смеси сохраняется.

**LB: 0.93.**

### Данные и разметка

Ручная разметка теста запрещена; тут используется псевдо-разметка моделью.
Берём кропы с `p_v1 < 0.03` или `p_v1 > 0.97` — **11 291 из 20 000 (56.5%)**. 

Уверенная метка превращает тестовый кроп в кроп **с известной ориентацией**: при `p > 0.97` его поворачиваем на 180
градусов и получаем прямой (5 601 кропов). 

В `meta.csv` файлы не копируются: путь к исходнику, флаг `rotate` и мягкая метка `y_soft = min(p, 1 − p)`.

### Модель и обучение (`src/model.py`, `src/dataset.py`)

`timm mobilenetv3_small_100` (1.52M параметров, ImageNet-претрейн), вход 32×256 RGB, один логит.
Антисимметричная голова `z = (f(x) − f(rot180 x)) / 2`: свойство `p(x) + p(rot180 x) = 1` встроено в
архитектуру, симметричные строки получают `p ≈ 0.5` автоматически, а сеть не может опираться на признаки,
не связанные с ориентацией. Из-за антисимметрии `loss(x, y) == loss(rot x, 1 − y)`, поэтому в train подаются
только прямые кропы с меткой `y_soft`; val — каждый кроп в обеих ориентациях.

Лосс --- BCE с мягкими метками (proper scoring rule, согласован с Brier). 
AdamW, OneCycle-расписание на 20 эпох (`--epochs 20`), 
обучение при получении `submission_v2.csv` остановил после 13-й (`--stop-after 13`), 
чекпоинт --- лучшая эпоха по val Brier. 

Аугментации только не меняющие ориентацию: масштаб (down→up для мелкого текста), поворот ±3 градуса, blur, шум,
JPEG, яркость/контраст, grayscale, инверсия, случайное окно 256 по ширине. **Flip'ов нет**. 
Длинные строки на инференсе: до 4 окон, среднее логитов.

### Валидация и калибровка (`src/calib.py`)

Val --- отложенные 15% псевдо-размеченных кропов. Это контроль переобучения и подбор температуры, но **не**
честная оценка качества: val состоит из «лёгких» кропов, на которых учитель уверен. 
Temperature scaling: `p = σ(z / T)`, `T` минимизирует Brier на val.
